# Possibility · 后端开发架构

> 配套文档：`技术设计文档.md`（数据模型/RLS/函数契约的完整定义在那）。本文只讲**后端模块拆解、开发依赖图（哪些并行/串行）、每个模块用什么技术**。
> 后端形态：Supabase（Postgres + 匿名 Auth + Storage + Edge Functions/Deno-TS）+ Claude。全部可在本机（Linux）产出与本地跑通。

---

## 1. 模块与服务清单

按职责分 7 组，共 17 个模块。每个模块标注：职责 / 依赖 / 技术 / 所处开发波次（见 §2）。

| ID | 模块 | 职责 | 依赖 | 技术栈 | 波次 |
|---|---|---|---|---|---|
| **INFRA** | 基础设施 | `supabase init`、本地 stack、`config.toml`、Secrets 注入 | — | Supabase CLI · Docker · Deno | W0 |
| **SCHEMA** | 数据模型 | 建表 / 索引 / 约束 migrations | INFRA | Postgres · SQL migrations | W1 |
| **AUTH** | 认证 | 匿名登录、JWT 配置、`verify_jwt` | INFRA | Supabase Auth (GoTrue) | W1 |
| **STORAGE** | 对象存储 | 音频桶 + 桶策略（仅本人读写） | INFRA · AUTH | Supabase Storage | W1→W2 |
| **PROMPTS** | 提示词 | 前门红线 / match / simulate / diary 的 system prompt | —（纯内容） | Prompt 工程 · TS 常量 | W1（可提前） |
| **SCHEMAS** | 输出契约 | 结构化函数的 JSON Schema | —（纯内容） | JSON Schema | W1（可提前） |
| **SEEDGEN** | 种子生成脚本 | 原型 HTML 里 `USERS/PROFILE_META/...` → `seed.sql` | —（脚本） | Deno/Node 一次性脚本 | W1（可提前） |
| **RLS** | 行级安全 | 每表 RLS 策略（公开只读 / 锁 `auth.uid()`） | SCHEMA | Postgres RLS | W2 |
| **SEED** | 种子灌入 | 跑 `seed.sql` 灌 5 位旅人+服务+悬赏 | SCHEMA · SEEDGEN | SQL | W2 |
| **EF-SHARED** | 函数公共层 | Anthropic client 单例、JWT 校验、入参校验、错误封装、SSE helper、CORS、prompts/schemas 引用 | INFRA · PROMPTS · SCHEMAS | Deno · `npm:@anthropic-ai/sdk` · `_shared/` | W2 |
| **EF-CHAT** | 对话函数 | 流式回复 + 并行岔路口/画像信号 | EF-SHARED · SCHEMA(messages/conversations/profiles) | Deno · SSE · `claude-opus-4-8`(+`haiku-4-5`) | W3 |
| **EF-MATCH** | 匹配函数 | 3 位结局不同旅人 + 匹配理由（结构化） | EF-SHARED · SEED(travelers) | Deno · `claude-opus-4-8` · `output_config.format` | W3 |
| **EF-SIMULATE** | 推演函数 | 3 种未来结局（结构化） | EF-SHARED · SCHEMA(simulations) | Deno · `claude-opus-4-8` | W3 |
| **EF-DIARY** | 日记分析 | 情绪 + 关键词（+画像更新） | EF-SHARED · SCHEMA(diary_entries) | Deno · `claude-haiku-4-5` | W3 |
| **STT** | 语音转写（可选） | audio → transcript | STORAGE · EF-SHARED | Whisper API / iOS Speech | W3（可后置） |
| **TEST** | 测试 | 契约测试 / RLS 测试 / 集成冒烟 | 各 EF · RLS | Deno test · `functions serve` · curl | W4 |
| **DEPLOY** | 部署 | `db push`、`functions deploy`、`secrets set`、CI | 全部 | Supabase CLI · GitHub Actions | W4 |

> **服务边界**：Supabase 自带 Kong 网关，4 个 Edge Function 各自路由在 `/functions/v1/<name>`，**无需自建 API Gateway**。函数间不互相调用（除 `chat` 内部并发 Haiku），无服务网格需求。

## 2. 开发依赖图（并行 / 串行）

核心判断：**基础设施是唯一硬串行前置；提示词/契约/种子脚本是纯内容可即刻开跑；4 个 Edge Function 之间完全独立、可全并行。**

```
即刻可起(无依赖) ┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┐
  PROMPTS · SCHEMAS · SEEDGEN  ────────────────┐        │
                                               │        │
W0 串行前置                                     │        │
  ┌──────────┐                                 │        │
  │  INFRA   │                                 │        │
  └────┬─────┘                                 │        │
       │                                       │        │
W1 并行 ├── SCHEMA ──┐                          │        │
       ├── AUTH      │(并行)                    │        │
       └── STORAGE   │                          │        │
                     │                          │        │
W2 并行         ┌────┴──────┬─────────────┐     │        │
            RLS │      SEED │       EF-SHARED ◀─┘(用 PROMPTS/SCHEMAS)
           (需SCHEMA) (需SCHEMA+SEEDGEN)  │
                                          │
W3 全并行（4 函数互不依赖）        ┌───────┴────────┬──────────┬──────────┐
                              EF-CHAT       EF-MATCH   EF-SIMULATE  EF-DIARY
                             (需messages等)  (需SEED)  (需simulations)(需diary)
                                                                     └─ STT(可选)
W4 并行
                                   TEST ──────────────── DEPLOY
```

### 波次说明
| 波次 | 内容 | 并/串 |
|---|---|---|
| **t0（无依赖，可先起）** | PROMPTS · SCHEMAS · SEEDGEN | 三者互相并行，且与 INFRA 并行 |
| **W0** | INFRA | **串行前置**，DB/Auth/Storage/EF 全依赖它 |
| **W1** | SCHEMA · AUTH · STORAGE | 三者并行（都只依赖 INFRA） |
| **W2** | RLS · SEED · EF-SHARED | 三者并行；RLS/SEED 依赖 SCHEMA，EF-SHARED 依赖 INFRA+PROMPTS+SCHEMAS |
| **W3** | EF-CHAT · EF-MATCH · EF-SIMULATE · EF-DIARY（+STT） | **4 函数完全并行**，各自依赖对应表 + EF-SHARED |
| **W4** | TEST · DEPLOY | TEST 与 DEPLOY 可并行推进（本地测好即可部署） |

### 关键路径（决定最短工期）
```
INFRA → SCHEMA → EF-SHARED → EF-CHAT → TEST → DEPLOY
```
`EF-CHAT` 是最复杂函数（流式 + 并发信号），落在关键路径上，**优先启动**。其余 3 个函数从 `EF-SHARED` 分叉并行，不占关键路径。`SEED/RLS/AUTH/STORAGE/PROMPTS/SCHEMAS` 全部**离关键路径**，可穿插填充空档。

### 建议并行编队（若多人/多 agent）
- **A 线（关键路径）**：INFRA → SCHEMA → EF-SHARED → EF-CHAT。
- **B 线（数据）**：SEEDGEN（提前）→ 等 SCHEMA 就绪后 SEED + RLS。
- **C 线（内容）**：PROMPTS + SCHEMAS 提前写好，喂给 A 线的 EF-SHARED。
- **D 线（其余函数）**：EF-SHARED 就绪后，EF-MATCH / EF-SIMULATE / EF-DIARY 三人各领一个并行。

## 3. `EF-SHARED` 公共层（4 函数的地基，务必先做）

放在 `supabase/functions/_shared/`，被 4 个函数 import。这是把「串行公共依赖」集中化、让 4 函数得以并行的关键。

| 子模块 | 职责 | 技术 |
|---|---|---|
| `anthropic.ts` | Anthropic client 单例（读 `Deno.env`） | `npm:@anthropic-ai/sdk` |
| `auth.ts` | 校验 Supabase JWT，取 `user_id`；失败 401 | `jose` / Supabase JWT |
| `validate.ts` | 入参类型/长度校验（message、transcript 上限） | 手写 + `zod`（可选） |
| `sse.ts` | `ReadableStream` + `text/event-stream` 封装 | Deno Web API |
| `errors.ts` | 统一错误响应 + 重试（429/5xx）、日志 | SDK 内置 retry |
| `prompts.ts` | 4 套 system prompt（含 §7.2 红线） | TS 常量（来自 PROMPTS） |
| `schemas.ts` | match/simulate/diary 的 JSON Schema | JSON Schema（来自 SCHEMAS） |
| `db.ts` | 用 service-role 或转发用户 JWT 写库（受 RLS） | supabase-js（Deno） |
| `cors.ts` | 预检响应（原生 App 不需，浏览器联调用） | 手写 headers |

> **安全基线**（防御纵深）：① Key 只在 Function Secrets；② 每函数 `verify_jwt=true` 校验 JWT；③ 写库经 RLS 二次约束；④ 入参长度/类型校验防滥用；⑤ 结构化输出全走 `output_config.format` 约束，不裸解析。

## 4. 运行时并行（与开发并行区分）

| 场景 | 并行策略 |
|---|---|
| 4 个 Edge Function | 各自独立部署、独立冷启动与扩缩，边缘运行时互不阻塞 |
| `chat` 函数内部 | 流式回复 与 岔路口/画像结构化判定 **并发**（`Promise.all`）；信号在 `event: done` 一并回传 |
| `match` | 单次 Opus 调用一次产出 3 条（省 token）；需要更强多样性时才 fan-out 成 3 并发 |
| App 侧 | `match` 请求 与 旅人主页公开数据（travelers/details）拉取 **并行**；对话历史与画像并行加载 |
| 日记 | 上传音频（Storage）→ STT → `analyze-diary` 为**串行链**；但多条日记之间可并行 |

## 5. 目录结构（后端仓）

```
supabase/
├─ config.toml                 # 项目/函数配置(verify_jwt 等)  ← INFRA
├─ migrations/
│  ├─ 0001_schema.sql          # 建表                          ← SCHEMA
│  ├─ 0002_rls.sql             # RLS 策略                      ← RLS
│  └─ 0003_storage.sql         # 桶 + 策略                     ← STORAGE
├─ seed.sql                    # 种子(脚本生成)                 ← SEED
├─ functions/
│  ├─ _shared/                 # 公共层                        ← EF-SHARED
│  │  ├─ anthropic.ts  auth.ts  validate.ts  sse.ts
│  │  ├─ errors.ts     prompts.ts  schemas.ts  db.ts  cors.ts
│  ├─ chat/index.ts            # ← EF-CHAT
│  ├─ match/index.ts           # ← EF-MATCH
│  ├─ simulate/index.ts        # ← EF-SIMULATE
│  └─ analyze-diary/index.ts   # ← EF-DIARY
└─ tests/                      # ← TEST (deno test + functions serve)
scripts/
└─ gen_seed.ts                 # 原型 HTML → seed.sql          ← SEEDGEN
```

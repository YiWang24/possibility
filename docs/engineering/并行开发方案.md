# 前后端接线并行开发方案(2026-07-25)

> 结论:后端 LLM 全部真实接入(Anthropic SDK → 面壁网关 → claude-sonnet-5,11 个 Edge Functions 均 verify_jwt)。
> 主要缺口是 iOS 前端未调用已就绪的后端接口。本方案按 3 个波次派发 subagent 并行开发。

## 保留的 seed/mock(不动)

- seed 演示数据:12 位旅人、traveler_details(1–5,波次 1 补 6–12)、通用服务、悬赏(reward 需清洗)
- demo 支付:`unlocks` 直写、PaywallView 模拟下单(无真实支付网关,维持现状)
- 静态游戏素材:测评题库(AssessmentData)、卡牌内容(CardGameData)、Lab 底线卡文案
- STT:可选项,用 iOS Speech 端上转写,后端无此能力

## 缺口清单

### 后端需补
1. seed:`bounties.reward = 'undefined'` 脏数据(`scripts/gen_seed.mjs` → `supabase/seed.sql:35-37`);旅人 6–12 无 details/services
2. `community` 缺 `get_bounty` action(悬赏详情 + bounty_responses 读取)
3. 日记月/年总结无接口(需新函数 `diary-summary`,LLM 聚合)

### iOS 未接线(后端已就绪)
- `/lab-choices`(LabModel.swift:31-36 硬编码)
- `simulate` 未传 `carry_cards`,未用 `bottom_line_analysis`/`recommended_traveler_ids`(SupabaseService.swift:234-247)
- `/match` 零调用点(Chat 岔路口 + Lab 相似旅人均本地筛选)
- `/persona` 未接(HomeModel 本地几何计算)
- `/list-conversations` + `loadMessages` 未调用(无历史会话)
- `save_card_game`(卡牌结果仅 UserDefaults)
- `save_public_profile`(Me 主页纯本地 `kaleido_my_profile_v1`)
- `community` 悬赏 list/create/respond 未接(详情页用 DemoData.bountyDetail)
- Chat 验证/纠正循环是本地插值(ChatModel.swift:91-131),应作为续轮消息发回 `/chat`(后端多轮已支持)
- Home 用户名/探索天数/周历硬编码(HomeModel.swift:207-208、HomeView.swift:151-154)

## 波次 1 — 契约层(2 agent 并行)

### T1-后端补齐(仅改 supabase/、scripts/)
- 清洗 seed reward;补旅人 6–12 details/services seed
- `community` 增 `get_bounty` action(入参 `{bounty_id}`,出参悬赏详情 + responses 列表)
- 新增 `diary-summary` 函数:按月/年聚合 diary_entries + LLM 洞察,复用 `_shared/` 规范
- 补 validate/schema 单测
- 验收:`npm run backend:check` && `npm run db:test`

### T1-iOS 网络层(仅改 Core/Network/、Core/Models/、App/AppConfig.swift)
- SupabaseService 加齐:personaGenerate/status、labChoices、listConversations、
  communityListBounties/createBounty/respondBounty/getBounty、saveCardGameRemote、
  savePublicProfileRemote、fetchRemoteProfile 全量解码、simulate 补 carry_cards + bottom_line + recommended_traveler_ids
- Codable 模型对齐 `_shared/schemas.ts`(snake_case)
- 验收:`xcodebuild build` 通过

## 波次 2 — 六个 feature agent 全并行(worktree 隔离,只改各自 Features/ 目录)

| Agent | 目录 | 任务 | 验收 |
|---|---|---|---|
| A-Lab | Features/Lab/ | 接 /lab-choices(硬编码为兜底);simulate 传 carry_cards;展示 bottom_line_analysis;相似旅人用 recommended_traveler_ids | 提问→动态卡→推演→三结局+底线分析全链路 |
| B-Chat | Features/Chat/ | 验证/纠正走 /chat 续轮;岔路口调 /match 展示 3 位旅人;接 list-conversations+loadMessages 历史恢复 | 多轮连贯;真实匹配;重启历史可见 |
| C-Home | Features/Home/、Features/Diary/ | 接 /persona(本地为兜底);周历从 list-diary 聚合;探索天数真实推算;月/年总结接 diary-summary;可选 iOS Speech STT | 日记→分析→周历/总结真实;数字人来自后端 |
| D-Me | Features/Me/ | MyProfile 读写走 save_public_profile + get-profile.public_profile;visibility 映射展示开关 | 保存→清本地→云端恢复 |
| E-CardGame | Features/CardGame/ | 结果上云 save_card_game;启动回读 get-profile.card_games | 完成局→清本地→结果仍在 |
| F-Community | Features/Community/ | 悬赏列表/详情走 list_bounties/get_bounty;加发布/回应入口 | 发悬赏→可见→可回应→详情真实回应 |

依赖:全部依赖波次 1;F、C 额外依赖 T1-后端的 get_bounty / diary-summary。

## 波次 3 — 集成验证

- G-联调:`supabase start` + `functions serve` 全函数 curl 冒烟;backend:check、db:test、xcodebuild;六大主线手测
- H-评审:合并后 `/code-review`,重点:兜底模式不被破坏(真实优先+静默回退)、RLS、契约一致性

## 合并顺序

T1-后端、T1-iOS 先合入 → 六个 feature 分支逐个 rebase 合入(目录互斥)→ 波次 3。

## 通用约束(写进每个 agent 的 prompt)

1. 保持现有"真实调用优先 + 本地兜底"模式,不得因接线失败让页面白屏
2. iOS feature agent 不得改 Core/、App/、其他 Features/ 目录
3. 后端改动必须过 `npm run backend:check`;涉及表/RLS 必须补 rls_test.sql
4. LLM key 只存 Supabase Secrets,不进 xcconfig/代码
5. 提交信息沿用仓库中文 conventional commit 风格(feat(frontend)/feat(backend))

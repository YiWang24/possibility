# 埋点方案（Analytics Instrumentation Spec）

> 本文件是**唯一事实来源**。Swift 侧镜像
> `ios/Possibility/Core/Analytics/AnalyticsEvent+Catalog.swift`，
> TypeScript 侧镜像 `supabase/functions/_shared/events.ts`。三者事件名与属性必须一致，
> 改动先改本文件，再同步两侧镜像。

## 0. 架构：三层，各司其职

| 层 | 载体 | 负责 | 数据主权 |
|---|---|---|---|
| Layer 1 | Postgres `app_events` 表 | 服务端事实 + 客户端事件副本，SQL 算漏斗/留存 | 自己 |
| Layer 2 | PostHog（`posthog-ios`） | 客户端行为、现成漏斗/留存/cohort UI、录屏 | 第三方 |
| Layer 3 | Sentry（`sentry-cocoa` + Edge envelope） | 崩溃、错误、前后端 request_id 串联 | 第三方 |

**为什么 Layer 1 和 Layer 2 事件重复上报**：PostHog Cloud 在国内网络可达性不稳定，
一旦上报失败数据永久丢失。`app_events` 是兜底的事实表，也是唯一能和 `match_results`
/ `lab_choice_sets` 等业务表 JOIN 的地方。PostHog 只是"好用的看板"，不是数据源。

这里的“重复上报”是指**同一事实分别进入 app_events 与 PostHog**，不是在
`app_events` 内存两行。服务端可确认成功的事实以服务端为 Layer 1 唯一来源；
iOS 对同一事件只补 PostHog / Sentry。纯本地事件才由 iOS 写 `app_events`。

## 1. 命名规范

- 事件名：`object_action`，snake_case，过去式（`paywall_viewed` 而非 `view_paywall`）
- 属性名：snake_case，值类型只允许 string / int / double / bool
- 不在事件名里编码变量（不要 `paywall_viewed_unlock`，用属性 `sku: "unlock"`）
- 禁止在属性中写入个人身份信息：手机号、姓名、日记正文、对话正文。
  需要长度/特征时上报派生值（`content_chars: 128`）。
- Sentry 中 Supabase UUID 必须先做 SHA-256 单向摘要；`sendDefaultPii=false`
  不会自动清理应用手工设置的 user / breadcrumb 数据。

## 2. 用户标识

| 概念 | 来源 | 说明 |
|---|---|---|
| `distinct_id` | PostHog 生成的设备匿名 ID | 安装即产生，贯穿匿名期 |
| `user_id` | Supabase `auth.users.id` | 匿名会话也有（`signInAnonymously`），转正后可能变化 |
| `anonymous_id` | 转正前的旧 `user_id` | 仅在 `identity_merged` 事件中出现 |

**关键约束**：App 启动即 `signInAnonymously()`，所以任何时刻都有 `user_id`。
Apple 登录会产生**新的** `user_id`（旧匿名数据由 `merge-anonymous` 迁移）；
手机号转正 `user_id` 不变。

因此 PostHog 的身份处理规则是：

1. 冷启动：`identify(userId)`，不带 alias
2. 手机号转正：`user_id` 不变 → 只更新 person properties，不调 alias
3. Apple 登录（`user_id` 变化）：先 `alias(oldUserId, newUserId)` 再 `identify(newUserId)`
   —— **漏掉这步，匿名期行为会成为孤儿事件，"进入→付费"完整漏斗直接断裂**

## 4. `app_events` 表结构

```sql
create table app_events (
  id            bigserial primary key,
  event_id      uuid not null unique,
  user_id       uuid references auth.users(id) on delete set null,
  event         text not null,
  props         jsonb not null default '{}',
  source        text not null check (source in ('ios', 'server')),
  session_id    text,
  app_version   text,
  created_at    timestamptz not null default now()
);
```

- `on delete set null`：用户注销后事件保留但去标识化，聚合指标不塌陷，
  同时满足个人信息删除要求（`delete-account` 需同步确认口径一致）。
- RLS：`authenticated` 仅可 `insert` 且 `user_id = auth.uid()`；**任何人不可 select**
  （分析走 service_role / Dashboard SQL）。防止用户互相读取行为数据。
- 客户端 RLS 还强制 `source = 'ios'` 和 iOS 事件白名单，不能伪造
  `llm_request` / `crossroad_formed` 等服务端事实。
- `event_id` 是重试幂等键；“服务端已提交但客户端没收到响应”时重放不会双计。
- `app_event_user_aliases` 与 BEFORE INSERT trigger 会把登录切换期间迟到的匿名事件
  重定向到正式账号，避免 `deleteUser` 把它们变成无主事件。
- 索引：`(event, created_at desc)`、`(user_id, created_at desc)`。
- 当前量级（刚上线）不做分区；日均事件破 10 万后再按月分区。

## 5. 核心指标定义

- **岔路口形成率** = `crossroad_formed` 用户数 / `chat_started` 用户数
- **付费转化率** = `purchase_completed` / `paywall_viewed`
- **漏斗全链路转化** = `purchase_completed` 用户数 / `app_opened` 用户数
- **留存**：按 `app_opened` 首日分 cohort，看 D1 / D7 / D30
- **对话深度**：到 `crossroad_formed` 所需的 `turn_index` 中位数

## 6. 故障串联与运行监控

- iOS 每次 Edge Function 请求生成 `X-Request-ID`。
- Edge Function 复用安全格式的 ID；错误 JSON、SSE error、响应头、结构化日志与
  Sentry tag 使用同一个 `request_id`。
- iOS Console 与 Sentry breadcrumb 只记录函数名、request_id、错误类型，不记录正文。
- 运行健康查询见 `supabase/analytics/observability.sql`，至少监控：
  最近事件时间、按 source 的采集量、近期无主事件率、LLM 失败率/P95、近似重复事件。
- Deno 依赖以 `supabase/functions/deno.json` 和 `deno.lock` 为部署事实来源；
  流式重试行为必须在该固定版本上验证。

建议初始告警阈值（有一周真实基线后再调整）：

- 生产有活跃用户时，任一核心事件超过 30 分钟无新数据；
- `llm_request` 15 分钟窗口失败率 > 10% 或 P95 > 45 秒；
- 最近 24 小时 `user_id is null` 比例 > 1%；
- 服务端权威事件在 `app_events` 出现跨 source 近似重复。
